# DC02: Secondary Domain Controller

| | |
|---|---|
| **Role** | Domain controller, DNS, DHCP (failover partner) |
| **OS** | Windows Server 2022 Standard *(example)* |
| **IP** | 10.0.20.11 (VLAN 20), static |
| **Host** | VM on HV01 |
| **Specs** | 2 vCPU / 4 GB RAM (static) / 60 GB disk |
| **Installed roles** | AD DS, DNS Server, DHCP Server |
| **FSMO roles** | None (all on DC01) |
| **Global Catalog** | Yes |
| **Backup** | Windows Server Backup, System State to NAS01 |
| **Last reviewed** | 2026-11-03 |

## Purpose

Redundancy. If DC01 is down, logons, DNS, and DHCP continue. Both DCs live on the same Hyper-V host, so this protects against a VM or OS failure, **not** a host failure. See [backup.md](../services/backup.md) for the host-failure plan.

## Verification commands

```powershell
dcdiag /q
repadmin /replsummary
repadmin /showrepl
Get-DhcpServerv4Failover
```

## If DC01 is permanently lost

1. Seize FSMO roles to DC02: `Move-ADDirectoryServerOperationMasterRole -Identity DC02 -OperationMasterRole 0,1,2,3,4 -Force`
2. Clean up DC01's metadata (AD Sites and Services / `ntdsutil` metadata cleanup).
3. Build a replacement DC and promote it.
4. Never bring the old DC01 back online once its roles have been seized.
